### 3.2 选项式 API 基本语法（`01-basic.html`）

按实验给出的语法骨架，建立第一个 Vue 应用：

```js
const { createApp } = Vue

createApp({
  data() {                 // ① 状态
    return { count: 0, price: 99, qty: 2 }
  },
  computed: {              // ② 派生状态（有缓存）
    total() { return this.price * this.qty }
  },
  methods: {               // ③ 动作
    add() { this.count++ }
  },
  watch: {                 // ④ 副作用
    count(newVal, oldVal) { console.log(oldVal, '→', newVal) }
  },
  mounted() {              // ⑤ 生命周期：DOM 已就绪
    console.log('挂载完成')
  }
}).mount('#app')
```

**为验证"computed 有缓存"这一结论**，做了一个可观察的对照实验：页面上同时显示 `computed` 的 `total` 与 `methods` 的 `getTotal()` 结果，并各自统计"实际求值次数"。

- 修改 `price` 或 `qty` → `computed` 求值次数 +1（依赖变了才重算）；
- 只点"触发重渲染"（修改一个与 total 无关的变量 `tick`）→ 页面重新渲染，但 `computed` 求值次数**不增长**。

这说明：**computed 的结果会随依赖缓存，methods 每次调用都会重新执行**。这也是"派生值优先用 computed、不要用 methods"的原因。

此外通过 `created → beforeMount → mounted` 的日志时间线，验证了"只有 `mounted` 之后才能读到元素的真实尺寸"（在 `created` 中读 DOM 高度只能是 0）。

### 3.3 常用指令及其修饰符（`02-directives.html`）

按实验要求逐个验证，重点做了两组"对比实验"：

**（1）`v-if` 与 `v-show` 的差异**

用同一个布尔变量控制两块内容，并提供一个"重新检测"按钮，用 `document.querySelector` 现场检查节点是否存在：

```js
probeDom() {
  this.domProbe = {
    hasIf: !!document.querySelector('#box-if'),
    hasShow: !!document.querySelector('#box-show')
  }
}
```

结果：切换后 `#box-if 存在 = false`，`#box-show 存在 = true`（只是 `display: none`）。
**结论**：`v-if` 是"销毁/重建"（切换成本高、初始成本低），`v-show` 是"改样式"（切换成本低、初始成本高）。频繁切换用 `v-show`，条件很少变或需要清空组件状态用 `v-if`。

**（2）`v-text` / `v-html` / `v-once` / `v-pre` 的差异**

四个面板渲染同一份可变字符串 `<b>加粗</b> 与 <em>斜体</em>`，修改输入框后观察：

| 指令 | 表现 | 结论 |
| --- | --- | --- |
| `v-text` | 原样显示尖括号 | 写入纯文本 |
| `v-html` | 显示为加粗/斜体 | 按 HTML 解析，**有 XSS 风险，不可用于用户输入** |
| `v-once` | 内容不再变化 | 只渲染一次，跳过后续更新 |
| `v-pre` | 原样显示 `{{ rawHtml }}` | 跳过编译 |

**（3）事件修饰符**

用一个"外层 div 套内层 div"的结构验证 `.stop`：点内层时日志只出现"内层 .stop"一条；去掉 `.stop` 后会出现"外层收到点击"。`.prevent` 用一条 `href` 指向 Vue 官网的链接验证——加了 `.prevent` 后点击不跳转。`.once` 连点三次只记录一条。

**（4）表单修饰符**

`.trim` 让输入的 `  张三  ` 变成 `张三`；`.number` 让输入框的值类型变为 `number`（页面直接打印 `typeof`）；`.lazy` 让 textarea 只在失焦后同步。

### 3.4 博客首页重构（`03-blog.html`）

数据仍沿用实验4 的模拟数据，单独抽到 `js/data.js`（文章 4 篇、留言 3 条）。重构分三步：

**第一步：文章列表改用 `v-for`**

```html
<article v-for="(article, i) in filteredArticles" :key="article.id">
  <h3>{{ article.title }}</h3>
  <p>{{ article.summary }}</p>
  <span class="tag" v-for="t in article.tags" :key="t">{{ t }}</span>
</article>
```

实验4 中这里是 `for` 循环 + `innerHTML +=` 拼字符串；现在只保留一个 `v-for`，渲染多少条由数组长度决定，头部"共 4 篇文章"也由 `articles.length` 自动得出。

**第二步：标题搜索**

把搜索拆成"输入值"与"生效词"两个状态，避免边打边筛：

```js
data()   { return { keyword: '', activeKeyword: '' } },
computed: {
  filteredArticles() {
    const kw = this.activeKeyword.toLowerCase()
    if (!kw) return this.articles
    return this.articles.filter(a =>
      a.title.toLowerCase().includes(kw) ||
      a.summary.toLowerCase().includes(kw) ||
      a.tags.some(t => t.toLowerCase().includes(kw)))
  }
},
methods: {
  search() {                             // 回车或点击「搜索」时执行
    const kw = this.keyword.trim()
    if (!kw) return this.resetSearch()
    this.activeKeyword = kw
  }
},
watch: {
  keyword(newVal, oldVal) {              // 只负责记录副作用
    this.watchState = { newVal, oldVal, hits: this.watchState.hits + 1 }
  }
}
```

- 输入框每敲一个字 → `watch` 触发次数 +1（页面可观察）；
- 只有按回车（`@keydown.enter`）或点击按钮后 → 列表才变化；
- 命中关键词在标题中高亮：把标题先做 HTML 转义，再用 `v-html` 插入 `<mark>`（**内容可控 + 已转义，属于 `v-html` 的合规用法**）；
- 搜索 `zzz` 时 `filteredArticles.length === 0`，`v-if` 显示"没有匹配的文章"空状态。

**第三步：留言列表**

```html
<form class="msg-form" @submit.prevent="addMessage">
  <input v-model.trim="newMessage.name"    maxlength="32">
  <input v-model.trim="newMessage.content" maxlength="120">
  <button type="submit" class="btn">发表留言</button>
</form>
```

`@submit.prevent` 拦掉表单默认的"提交并刷新"，因此 input 里直接按回车也能提交，无需单独监听键盘。校验规则：姓名/内容为空拦截、内容超过 100 字拦截，并给出红色提示。

删除留言用不可变写法：

```js
delMessage(id) {
  this.messages = this.messages.filter(m => m.id !== id)
}
```

页面还提供了"留言按姓名/内容搜索"，验证 `v-for` 渲染的是 `filteredMessages` 而非原数组。

**三步重构完成后**，页面上附了一张"实验4 原生写法 vs 实验5 Vue 写法"的对照表（渲染文章、取输入值、监听回车、阻止刷新、过滤数据、删除留言、空状态共 7 组），用于直观对比两种范式。

### 3.5 Todolist 经典案例

**阶段一（`04-todolist.html`）**：按实验文档的最小实现，去掉"添加"按钮，用表单回车提交：

```js
add() {
  const text = this.taskText.trim()
  if (!text) return this.$refs.taskInput.focus()
  this.todos.push({ id: Date.now(), text, done: false })
  this.taskText = ''
},
del(index) { this.todos.splice(index, 1) }
```

验证结果：输入"任务 4"回车 → 列表新增一行、输入框清空；点"删除"→ 对应行消失、`共 N 项任务` 同步变化；删空后显示空状态；全部完成时底部出现"全部完成 🎉"标签。

**阶段二（`05-todolist-plus.html`）**：在基础版上实现实验要求的四项新增功能。

| 新增功能 | 实现要点 |
| --- | --- |
| ① 完成状态 | `<input type="checkbox" v-model="todo.done">` 直接绑对象属性；文字用 `:class="{ done: todo.done }"` 加删除线 |
| ② 点击"编辑"→ p 变 input | 用 `editingId` 记录正在编辑的行，`v-if / v-else` 在 `span` 与 `input` 间切换；绑临时副本 `editingText`，不直接绑 `todo.text` |
| ③ 失焦 / 回车保存，Esc 取消 | `@blur`、`@keyup.enter` 共用 `saveEdit()`；`@keyup.esc="cancelEdit"` |
| ④ 分类统计 | `computed stats()` 从 `todos` 派生 `{ total, done, active }`，不额外维护计数器 |

编辑功能的三个关键点：

```js
startEdit(todo) {
  this.editingId = todo.id
  this.editingText = todo.text
  this.$nextTick(() => {                       // input 渲染出来后才能聚焦
    const el = this.$el.querySelector('.edit-input')
    el && (el.focus(), el.select())
  })
},
saveEdit(todo) {
  if (this.editingId !== todo.id) return       // 幂等：回车后 input 销毁会再触发 blur
  const text = this.editingText.trim()
  if (text) todo.text = text                   // 空内容视为放弃修改
  this.editingId = null
}
```

此外还补充了：筛选（全部/未完成/已完成）、全部完成、清除已完成、进度条、`localStorage` 持久化（键名 `lab5-todos`，用 `deep: true` 的 watch 落盘）、恢复初始数据。

## 五、遇到的问题与解决

| # | 问题现象 | 原因分析 | 解决方案 |
| --- | --- | --- | --- |
| 1 | `04-todolist.html` 整页空白，控制台报 `Cannot read properties of undefined (reading 'text')`，并提示 `Property "todo" was accessed during render but is not defined on instance` | 页面底部"完整代码"折叠块里，为演示而写的 `{{ todo.text }}` **没有做 HTML 转义**，被模板编译器当成真实插值表达式，在 `v-for` 作用域之外执行 | 给 `<pre class="code">` 加 `v-pre`，让编译器整体跳过该节点；同时养成"代码示例块一律 `v-pre`"的习惯 |
| 2 | 生命周期面板报 `el.getBoundingClientRect is not a function`，高度一直是 0 | 根组件有多个根节点时，`this.$el` 拿到的是 **Fragment 的首个节点（可能是注释占位节点）**，不是元素 | 改用 `document.getElementById('app')` 取挂载容器后再测量 |
| 3 | 想在页面上"看见"computed 的求值次数，直接在 getter 里 `this.calls++` 后报 `Maximum recursive updates exceeded` | `computed` getter 里同步修改响应式数据 → 数据变 → 重新求值 → 再改，形成死循环 | 用 `setTimeout(..., 0)` 把计数推到求值结束之后；并在注释中说明"这只是教学观察手段，真实项目里 computed 不应有副作用" |
| 4 | 最初想在 `updated()` 里记录"DOM 已更新"的日志，结果日志无限增长 | 在 `updated` 钩子里 `push` 数据 → 又触发更新 → 又进 `updated` | 改用 `$nextTick()` 在方法中记录一次，时机等价且安全 |
| 5 | 编辑任务时，按回车保存后控制台出现两条保存日志 | 回车保存后 `input` 被销毁，浏览器仍派发一次 `blur`，`saveEdit` 被执行两次 | 让 `saveEdit` 幂等：先判断 `editingId === todo.id`，处理完立刻置空 |
| 6 | 首次加载时页面上会闪一下 `{{ }}` | 模板在 Vue 编译完成前已由浏览器渲染出原始文本 | 根节点加 `v-cloak`，CSS 中 `[v-cloak] { display: none }` |
| 7 | 代码块中"数据探针"面板的多行文字挤成一行 | Vue 编译器默认 `whitespace: 'condense'`，会丢弃元素之间的纯换行文本节点 | 每行用 `<span class="pl">`（`display: block`）包裹，不依赖源码换行 |

## 六、实验小结

1. **换了一种"指挥方式"**。实验4 里我关心的是"哪个节点、改哪个属性"；实验5 里只关心"数据是什么、数据怎么变"。`v-for` 替代了循环 + `innerHTML` 拼接，`v-model` 替代了取值 + 回写，`filter` 替代了 `removeChild`。代码变短的背后，是**状态与视图解耦**：状态唯一，视图就可预测。

2. **computed / watch / methods 三者的边界**是本次最需要想清楚的地方：computed 算"值"（有缓存、无副作用），watch 做"事"（有副作用、不参与渲染），methods 处理"交互"（每次调用都执行）。想清楚这条边界，`keyword` 与 `activeKeyword` 该拆成两个变量就变得很自然。

3. **指令是语法糖，不是魔法**。`v-model` 就是 `:value` + `@input`，`@click.prevent` 就是"先 `preventDefault` 再调函数"，`v-if` 与 `v-show` 的差别本质是"销毁节点"与"改 display"。理解了编译结果，`02-directives.html` 里十几个面板就不需要死记，都能推导出来。

4. **踩坑本身也是收获**。第 1 个问题（代码块里的 `{{ }}` 被编译）让我第一次真正意识到"DOM 内模板 = 整段 HTML 都是模板"，连注释和示例代码都不例外；第 3、4 个问题让我理解了"在派生值里做副作用"为什么会引发循环更新——这些都是在只看语法、不动手的情况下永远不会遇到的问题。

5. **不足与改进方向**：目前数据是内存 + `localStorage`，没有后端与路由；页面之间用超链接而非 SPA 路由跳转；Vue 用的是 513 KB 的开发版，只适合教学。后续可以把 `server.js` 扩成带 REST 接口的服务，把文章卡片、留言项抽成组件，再用组合式 API 重写一遍，对比两种 API 的差异。
