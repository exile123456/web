watch 观察 keyword 的变化 watchState = { newVal: "{{ watchState.newVal }}", oldVal: "{{ watchState.oldVal }}", 触发 {{ watchState.hits }} 次 } 说明 = 输入框每敲一个字都会触发 watch；但列表只在按下回车 / 点击搜索后才变化，因为过滤依据是 activeKeyword（提交后的词），不是 keyword 本身。
关键逻辑：keyword / activeKeyword / computed / watch 是怎样协作的 
data() {
  return {
    keyword: '',        // 输入框的值，v-model 双向绑定
    activeKeyword: '',   // 真正参与过滤的词，只有"提交"时才写入
    searchHistory: []
  }
},

computed: {
  // 派生数据：依赖 activeKeyword 与 articles，两者任一变化才会重新计算
  filteredArticles() {
    const kw = this.activeKeyword.toLowerCase()
    if (!kw) return this.articles
    return this.articles.filter(a =>
      a.title.toLowerCase().includes(kw) ||
      a.summary.toLowerCase().includes(kw) ||
      a.tags.some(t => t.toLowerCase().includes(kw))
    )
  }
},

methods: {
  search() {
    const kw = this.keyword.trim()
    if (!kw) return this.resetSearch()
    this.activeKeyword = kw
    if (!this.searchHistory.includes(kw)) this.searchHistory.unshift(kw)
  }
},

watch: {
  // 侦听器负责"副作用"：记录日志、控制台输出，不参与渲染
  keyword(newVal, oldVal) {
    this.watchState = { newVal, oldVal, hits: this.watchState.hits + 1 }
  }
}

实验4（原生 JS）与实验5（Vue）的写法对照

重构收获
操作 实验4 原生写法 实验5 Vue 写法
渲染文章 遍历数组，innerHTML += 拼 HTML 字符串 v-for="a in filteredArticles" :key="a.id"
取输入值 document.querySelector('#kw').value v-model="keyword"
监听回车 addEventListener('keydown', e => e.key === 'Enter') @keydown.enter="search"
阻止刷新 e.preventDefault() @submit.prevent="addMessage"
过滤数据 手动 filter 后重新拼 HTML computed filteredArticles（自动缓存 + 自动重算）
删除留言 找到 DOM 节点后 parentNode.removeChild messages = messages.filter(m => m.id !== id)
空状态 创建/移除提示节点 v-if="list.length === 0"

核心差别只有一句：以前是"拿到数据 → 手动改 DOM"，现在是"只管改数据 → Vue 负责改 DOM"。 代码量减少只是副产品，真正的好处是"状态唯一、视图可预测"。
